## 1. 继承原则（仅列 M3+ 新增强化）
1. **包时间全栈统一【设计】**：规则窗口、告警冷却、会话老化、Agent 超时判定基准，一律使用**包时间戳**（分析时钟 = 已见最大包 ts）。任何墙钟参与业务判定均为 bug（M2v0.2§4.3 延伸至规则层与 Agent 层）。
2. **单一写入方【设计】**：所有业务表（`analysis_tasks/captures/sessions/alerts/agent_runs//findings`）仅 Rust 侧写入。Python Agent 通过 RPC 提交，不直连数据库（ADR-018，§10）。
3. **隔离不崩溃延续**：单条规则加载失败、单次 LLM 调用失败、单条 finding 被 Reject，均不得终止任务；只有资源/配置/进程级故障才 Fatal（延续 M2v0.2§5 分级）。
4. **payload 默认不出海**：M3 规则只消费元数据事件；M4 中 payload preview 仅经 envelope（含 redact）进入 LLM；M5 报告引用 preview 时保留 redact 标记（§28 落地闭环）。

### 3.2 YAML DSL v1（严格 schema，全量）
```yaml
id: NET-TCP-SYN-BURST-001        # 正则 ^[A-Z][A-Z0-9]*(-[A-Z0-9]+)*-[0-9]{3}$；全局唯一
version: 1                        # 规则自身版本，alert 携带以追溯
name: TCP SYN 突发检测
severity: high                    # high | medium | low | info
scope: packet                     # packet | session（session 规则在 SessionSummary 事件评估）
match:                            # 白名单字段过滤器（AND 语义，全命中才入窗）
  protocol: tcp                   #   protocol: tcp|udp|icmp|...
  flags: { contains: [SYN], excludes: [ACK] }   # 仅 tcp；contains/excludes 数组，元素⊆{FIN,SYN,RST,PSH,ACK,URG,ECE,CWR}
  src_port: { gte: 1024 }         #   端口条件 gte|lte|eq|in:[..]
  dst_port: { in: [53] }
  dns: { qname_len_gt: 52, txt_len_gt: 100, entropy_gt: 3.5 }   # 仅 udp/53；消费 AppDetail::Dns【继承-M2v0.2§3】
  decode_layer: ipv4              # 仅 malformed 规则：decode_error 事件的 layer/code
  decode_code: truncated_header
threshold:
  metric: count                   # count | distinct_count | sum_bytes | ratio
  field: dst_port                 # distinct_count/sum_bytes 必填；ratio 分母=当前滑动窗口内 match 通过事件数（§3.3-2）【修订-审评C1】
  group_by: [src_ip]              # 子集 ⊆ {src_ip,dst_ip,src_port,dst_port,protocol,session,decode_code}
  window: 10s                     # ∈ {1s,5s,10s,30s,1m,5m}
  operator: gt                    # gt|gte|lt|lte|eq|neq
  value: 100
dedupe:
  per_group_cooldown: 1m          # 【新增】同 group 冷却，默认 1m；与 window 共用同一白名单（S4）【修订-审评C2】
description: >-
  单一源 IP 在时间窗口内产生大量未完成 TCP SYN……
tags: [tcp, dos, scan]
```

**静态校验器规则【设计，全部为编译期拒绝项】：**
| # | 校验 | 违规处置（严格/宽松） |
|---|---|---|

| S2 | metric 白名单；`distinct_count/sum_bytes` 必须给 `field` | 报错 / dead-letter |
| S3 | field ∈ 字段白名单（见 3.4 表） | 报错 / dead-letter |
| S4 | window、cooldown ∈ **同一白名单** `{1s,5s,10s,30s,1m,5m}`（cooldown 默认 1m）【修订-审评C2】 | 报错 / dead-letter |
| S5 | `flags` 仅 scope=packet+protocol=tcp | 报错 / dead-letter |
| S6 | `dns.*` 仅 protocol=udp + dst_port 53 | 报错 / dead-letter |

### 3.3 评估语义【设计，须有单测】
1. **事件驱动**：`pipeline` 在事件产生后、sink 之前调用 `evaluate(ev, now_ns=ev.ts)`；`scope: session` 规则仅在 `SessionSummary` 事件评估。**flush 不合成 SessionSummary 事件、不评估 scope:session 规则**——session 规则的评估机会只有会话聚合状态机自然产出的 SessionSummary 事件，flush 不得绕过状态机【修订-审评C6】。
2. **滑动窗口（迟到事件容忍）【修订-审评C3，采纳方案 (a)】**：每 `(rule_id, group_key)` 维护 `VecDeque<(ts_ns, metric_val)>` 与**该 group 自身的 `seen_max_ts`**：
   - 事件 match 通过 → **无条件入队**（多接口 pcapng 的 EPB 时间戳可能非单调，后到事件 ts 可小于全局分析时钟——评估接受迟到事件，**禁止以“ts < 窗口左缘”为由直接丢弃**，否则合法迟到事件被永久丢弃）；
   - 入队后更新 `seen_max_ts = max(seen_max_ts, ev.ts)`，随后弹出队首满足 `ts < seen_max_ts - window` 的项——**弹队只按各 group 自身 seen-max 推进**（不用当前事件 ts、不用全局分析时钟）；
   - 对队列聚合值与 threshold 比较；
   - **不变量（DoD 对拍，#22）**：同一事件集按 ts 排序的单调输入与多接口乱序输入，flush 后窗口聚合结果**逐值一致**；
   - **ratio 语义与边界【修订-审评C1】**：分母 = **当前滑动窗口内 match 通过事件数**（即该 group 队列长度，非任务累计）；分子 = 同窗口内 match 通过且命中 `field` 所指子条件（取值与 match 过滤器同语法，如 NET-DNS-TUNNEL-RATIO-001 的 TXT>100）的事件数；分子子条件 DSL 编码在 Checklist #15 TDD 定稿（#26）。分母为 0（空窗）时 ratio ≡ 0，**不得除零 panic**，且 0 不满足 gt/gte（S7 已约束 value ∈ (0,1]）。
3. **触发与冷却**：条件满足且该 group 不在冷却期 → 产出 `AlertCandidate`，记录 `first_packet/last_packet/first_ts_ns/last_ts_ns` 与窗口内证据；进入 `per_group_cooldown`（以**包时间**计）。冷却期内不重复告警，计数继续累计到 `Stats`。
4. **收尾 flush**：`TaskFinished` 前以**分析时钟（已见最大包 ts）**为 now 对全部未过期窗口做末次评估（消除“差一秒不告警”边界）；**flush 不合成 session 事件、不评估 scope:session 规则**（理由见 3.3-1）【修订-审评C4/C6】。
5. **内存预算 `WindowBudget`**（对齐 M2v0.2§6 风格）：
```rust
pub struct WindowBudget { pub max_groups: usize /*50_000*/, pub max_events_per_group: usize /*4096*/ }
```
超限：LRU 逐出最旧 group（并发一条 `StreamStateEvent` 不合适——用 `Stats` 内 `rule_window_evictions` 计数 + WARN 日志）；单 group 事件超限 → 只保留计数摘要，明细丢弃【设计】。**证据降级形态【修订-审评§四.5】：该路径产出的 AlertEvent 必须显式标记——`evidence.sample_packets = []` 且 `evidence.degraded = true`（§3.6），禁止静默产出弱化证据。**
### 3.4 metric field 白名单（S3 依据）
| field | 类型 | 来源 |
|---|---|---|
| `dst_port` / `src_port` | u16 | TransportInfo |
| `dst_ip` / `src_ip` | IpAddr | NetworkInfo |

## 5. M5 — Report 规格
### 5.1 架构（ADR-021）
```python
class ReportGenerator:
    def __init__(self, engine: EngineClient, agent_run_id: str, template_dir: Path): ...
    def generate(self, out_path: Path) -> ReportMeta   # ReportMeta{path, sha256, degraded: bool, unverified_count: int}
```
- 模板：`agent/templates/report.md.j2`，Jinja2 文件版本化（`template_version` 写入 front-matter）；
- 数据源全走 RPC（§4.2 client），Python 不碰 DB（ADR-018）；报告写盘后 `report_path` 回填 `agent_runs`（RPC `SUBMIT_FINDING` 附带或新 `SUBMIT_REPORT_META`——选后者，避免复用语义【设计】）。
### 5.2 九节结构与字段来源（对齐开发文档 §18，逐节映射）
| 节 | 来源 | 渲染规则 |
|---|---|---|
| 1 Executive Summary | findings（仅 accepted 的 rule_match/direct_observation/correlated_observation） | hypothesis 单列“待人工确认”；**本节数字必须全部有 evidence 引用（硬门禁，见 5.3）** |
| 2 Capture Overview | `get_capture_summary` + `get_task_artifacts` | 含 source sha256、时间范围、包/字节总数 |
| 3 Protocol Statistics | `get_protocol_stats` link/network/transport/application ×4 | 表格 top10/层 |
| 4 Top Conversations | `get_conversations` sort_by bytes|packets limit 20 | 列 `direction_basis`【继承-M2v0.2§4.3】 |
| 5 Rule Alerts | `check_alerts` 全量 | rule_id/version/hash、窗口证据、sample_packets |
| 6 Agent Findings | findings 表 | title/severity/basis/status/summary |
| 7 Evidence | 每条 finding 的 EvidenceRef[] | 引用格式见 5.3；末尾 Evidence 索引表 |
| 8 Limitations | 自动计算表（5.4） | 逐项计数，空项显式写“0 — 无此类限制” |
| 9 Analysis Trace | `query_history kind=` | 编号列表：step/tool/args 摘要/结果摘要/duration/status（**不渲染任何模型思维过程**，ADR-007） |
Evidence 引用格式：`[E-7] tc-000123 · S-00421 · packets 1821–3070`；索引表含 `_id, method, ref_id, ts`。**该格式成立的唯一前提是 §4.3 tc ID 硬契约**（envelope `_id` = 台账主键 = EvidenceRef `_id`）【修订-审评B2】。
### 5.3 反幻觉 lint（双保险第二道，评审§4.2 收口）
1. 渲染后提取报告全文中的**数值/IP/端口/session_id/rule_id**；
2. 建立合法集合 = 所有已接收 evidence 引用指向的 tool result 字段 ∪ 台账实体；
3. 分级处置【设计，ADR-020】：
   - **Executive Summary 违规 → 硬失败**：中止渲染 exit 4，报告不落盘（宁可无报告，不可带假结论）；
   - **正文违规**：替换为 `[unverified by engine]`，`unverified_count++`，报告头部加 `⚠ UNVERIFIED CONTENT: n items`，`agent_runs.status=degraded`，exit 0。
4. **V5 归属与 exit 4 拆注【修订-审评B1/C9，ADR-023】：** finding 提交时的 V5 与本节报告全文 lint 均在 Python——结构性理由：engine 不消费 LLM 自由文本，V5 无下沉条件（V4 已下沉 Rust，§3.8/§4.4）。exit 4 双语义（internal error / anti-hallucination hard failure）在 `docs/error-codes.md` 拆注（§6.5），stderr message 以 `anti-hallucination` 关键字区分。
### 5.4 Limitations 自动计算表【事实】§18.2
| 项 | 数据源 |
|---|---|
| 截断包（truncated） | Stats / captures 计数 |
| TCP 流 Incomplete / BufferOverflow / 全局预算逐出 | StreamStateEvent 聚合【继承-M2v0.2§4/6】 |
| decode_error 计数 top3 code | Stats |
| 不支持的 linktype 计数 | NonFatal 计数 |
| 加密不可见声明 | 存在 TLS 会话即自动附“TLS payload 未解密，结论限于元数据” |
| 索引降级 | `analysis_tasks.index_mode=CountersOnly` 时声明“逐包查询受限”【继承-M2v0.2§6.1】 |
| 规则窗口逐出数 | Stats.rule_window_evictions |
| Agent 预算触达 | agent_runs 预算字段 vs 配置 |
| **distinct_count 欠计**【修订-审评C5】 | 命中规则涉 `tls.sni`/`http.host` 指标时自动附注“仅统计单包可解析样本” |
### 5.5 `--full` 编排与降级（ADR-020）
```text
packetsage analyze <cap> --full --report report.md
  ① Rust: parse + rules + 落库 → task
  ② Rust: spawn python agent(run --task-id) → findings + tool trace
  ③ Rust: spawn python agent(report --task-id) → report.md + lint
失败矩阵:
  ②失败(LLM/ToolError) → ③仍执行，报告第6节写"Agent 阶段失败: <类别>"，status=degraded，exit 0 + stderr WARN
  ③ lint 硬失败(ExecSummary 撒数) → exit 4，不落盘
  ①失败 → exit 2/3，无报告
```
**exit 4 拆注【修订-审评C9】：** `③ lint 硬失败` 与 internal error 共用 exit 4——`docs/error-codes.md` 拆注双语义（§6.5）；③ 路径的 stderr message 必须含 `anti-hallucination` 关键字，保证 CI/脚本能机器区分两类 exit 4。
`chat --report` 亦可用（会话结束后生成）。M2v0.2§5.2 中 `--report` exit 5 标记解除。

## 12. 修订结语
v0.2 把《v0.1 审评意见》全部回收为可执行契约：
1. **流程硬伤补票（B1）**：冻结契约偏离以 ADR-023 登记——偏离本身不是问题，未经登记的偏离才是；M6 的 error-codes CI 一致性与文档溯源链条自此不断裂。
2. **两处集成期契约空洞（B2/B3）**：tc ID 三重身份以硬契约 + 发行校验关闭；8000 chars 收紧取代上游 64 KiB 并经《开发文档 v0.3 修订页》留痕——处理成本被压到最低时点（M4 集成第一周之前）。
3. **九处语义模糊（C1–C9）全部写死为单一解释**：乱序时间戳采纳方案 (a)（group 自身 seen-max 弹队），与 M2 包时间语义同源；flush 与 scope:session 的边界、双源路由、exit 4 拆注均有确定性表述。
4. **测试与 DoD 增补 7 项、待验证项 #21–#26 入册**——“文档意识 → 实现约束”的转化链在 M3～M6 继续生效。
