## 修复结果（2026-09-23）

改动只在桌面端前端三个文件：`desktop/src/App.tsx`（轮次装配的状态机）、新增的
`desktop/src/session.ts`（两条纯逻辑）、`desktop/src/components.tsx`（`channel → 泳道`
的映射改成从 `session.ts` 取，免得"排一种、画另一种"）。引擎 / sidecar / 协议一行没动。

**1 · 会话流的轮次装配**（第 28 条）——两个 bug 一起修。

* **假轮次**（「你：打开 redundant_stream1.pcapng」下面挂"这份抓包还没有结论"）：不是又有新
  路径在"打开抓包"时建轮——`liveTurnId` / `asked` 只有 `startInvestigation()` 会设。
  它是**存量数据**：09-22 那次修复之前的版本把每次打开抓包都归档进了本机历史，
  `loadHistory()` 原样读回来照画。现在载入时先过 `sanitizeTurns()`，把"过程 / 结论 / 收尾
  三空"的空壳轮次丢掉；`archiveLiveTurn()` 也过同一道门，新的也不会再产生。
* **点历史对话看不到那一轮**：`analyzePath()` 先 `setHistory([])`，而换 `task_id` 要等
  `await api.analyze()` 回来——中间那一次渲染仍然挂着**旧** task id，于是"`history` 一变
  就落盘"的那个 `useEffect` 把旧桶写成了 `[]`，上一份抓包跑过的轮次就这么没了（本机
  leveldb 里确实能看到好几个 `[]` 桶）。现在自动落盘删掉，只在**发起一轮 / 换抓包 / 切任务**
  这三处显式写，切换途中的半截状态不会再写进任何桶。
* 顺手补一条：当前还没归档的那一轮也注册进 `turnRefs`，左栏点它同样能滚过去（原来点它没反应）。

**2 · 时间线的泳道顺序**（第 29 条）：`timelineItems()` 现在**过滤完再排**——按轮分块
（`第 N 步` 那一行是块头），块内自上而下 `调用` → `思考` → `输出` → `拒绝`，块与块之间保持
先来后到（引擎预取仍在最前）。原来只按事件到达顺序排，"思考"的流式原文会压在工具调用上面。
`输出` 那一行也跟着回来了：**正在流**的正文仍然只画在结论卡里（一屏一处文字，第 12 条），
一轮结束、原文收进折叠项之后它才回到时间线，排在这一轮最下面——用户那句"把 LLM 输出移到
最下、调用移到最上"就是这两条（`timelineItems()` 原来的 `channel === "content"` 一行过滤
改成只在 `!item.done` 时过滤）。

## 第三轮（4.1.4）：用户实测 4.1.3 后报的两条

**1 · 推理强度存不下来**（用户："滑块仅能滑动，关闭后没有保存思考强度，在软件信息中看到
思考强度还是自动的"）。根因在**外壳**，不在滑块：`provider_save` 原来见
"没给 `api_key` + 这个 provider 需要 key"就直接报错——而模型面板按设计发的正是
`apiKey: null`（它的文案写着"key 沿用已保存的那一个"，界面上也确实没让人再填一遍 key）。
于是面板里的**每一次保存都在写 `provider.json` 之前就失败了**：换模型、调强度全都白调，
文件停在 9-21 那版（连 `thinking` / `effort` 两个字段都还没有），界面自然一直显示"自动"。

* 现在只有"需要 key **且** 凭据管理器里也没有"才算错（`key_action()`，`commands.rs`），
  四种情况都有单测：填了新 key / 留空但存过 / 留空且没存过（才报错）/ mock 与 local 不要 key；
* 顺手统一了 key 存进去前的 `trim()`；
* 另外把 `_version.py` 的取版本顺序改成**源树优先**（改完 `pyproject.toml` 不必再
  `pip install -e` 一遍）：就是这个坑让 `test_version_matches_pyproject` 今天红了两次。

**2 · 回答里带着没清掉的 JSON**（用户图二）：模型这一轮把收尾信封写成了

```text
[summary]: "从工具结果看，这份抓包……"
[findings]: [{"title": "……", "severity": "info", …}]
```

——键名带着方括号，**不是合法 JSON**，`_loads_json` 解析不了；旧实现走"散文就是回答"那条
兜底，于是把整段原文（连 findings 数组）当成了回答，界面上就是一段没清理的 JSON。

* 新增 `_salvage_summary()`（`provider.py`）：文本**以信封开头**时，按"`summary` / `answer` /
  `text` 字段值，截到 `findings` 之前"把人话取出来；普通散文一个字都不动（有反例测试
  钉住：回答里提到 `summary` / `findings` 这两个词不算信封）；
* 机器字段不丢：它们照旧在时间线的「输出 · 原文」那一行里，点开能看全文。
